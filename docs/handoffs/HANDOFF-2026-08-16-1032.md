**3. Athlete/coach timezone bug — fixed, PR open, not yet merged.**
**PR #100**: https://github.com/ryanssareen/daily-athlete/pull/100 (branch `fix/athlete-timezone-capture-utc-display`, commits `d7594f8` + `459deb9`). Root cause: `public.users.timezone` defaults to `'UTC'` (migration `0001`) and no code path anywhere in the app ever wrote a real value into it — confirmed by querying production directly. Full test suite green, no regressions. **This PR has not been reviewed/merged yet — that's the immediate next step.**

## Key decisions

- **Admin (service-role) client, not RLS-scoped, for all new self-service write routes** (`/api/plans/[id]/archive`, `/api/profile/timezone`) — even though RLS would technically permit the self-write. Reason: `@/auth/server`'s client is bound to the **cookie session only**; `resolveAuth()` validates a Bearer token (mobile) for its return value but never attaches it to that client's Postgrest requests. An RLS-scoped write would silently no-op (0 rows affected, no error) for mobile callers instead of erroring. This is now documented in both route files' comments and in `docs/solutions/athlete-timezone-capture.md`.
- **Archive and delete are separate actions** on plans (not collapsed into one "remove"), matching the schema's existing `status='archived'` (still browsable) vs `deleted_at` (hidden) distinction.
- **Timezone capture is self-healing (compare + PATCH on every session load), not a one-time signup step** — this corrects *existing* athletes on their next session, not just new signups. Mounted in both role layouts since the root cause (the column, the missing write) is identical for both roles.
- **Cherry-picked `athlete_strava_id` unique-index fix** (`79c1fc3`) from an unmerged branch early in the session — unrelated prod-drift bug found while surveying repo state, fixed opportunistically.
- Production Supabase testing was explicitly authorized by the user for this session (small user base, low risk) — a Supabase MCP server was connected and used with `execute_sql` (read-only queries) and via `vercel env pull` + a temporary `ALLOWED_TEST_HOSTS` edit in `apps/web/src/db/__tests__/setup.ts` (reverted after each test run — do **not** leave that edit in committed code). Docker/`supabase start` is **not installed** in this environment, so local DB-backed testing isn't possible here without it.
