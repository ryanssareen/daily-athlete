## Post-report follow-up: dark mode toggle still reloaded the page

### Dark mode reload-on-toggle · Athlete
- Observed: user reported the toggle still "auto reloaded" the page — confirmed by re-reading the shipped fix: the toggle was a `<form action="/api/theme" method="post">`, so every click was a real browser navigation (POST → 303 redirect → full GET), not a client-side change. The earlier "confirmed live" check only verified the theme *eventually* applied, not that it applied without navigating.
- Root cause: confirmed, by code inspection — three call sites (`app-nav.tsx` sidebar toggle, athlete settings page, coach settings page) all posted to `/api/theme` and relied on the resulting redirect's full-page GET to re-render `<html data-theme>` (set server-side in `app/layout.tsx` from the `da2-theme` cookie). Functionally correct (theme did apply, per the earlier 303 fix) but implemented as a full reload for what only needs to flip a CSS custom property.
- Fix: added `apps/web/src/components/theme-button.tsx`, a client component that flips `document.documentElement.dataset.theme` and writes the `da2-theme` cookie directly via `document.cookie` on click — no navigation, no network request. Extracted `apps/web/src/components/appearance-theme-buttons.tsx` so the athlete and coach settings pages share one implementation instead of two copies. `/api/theme` is left in place (unused by any client code now) rather than deleted.
